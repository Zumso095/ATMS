# Исправление дублирования UI гаджетов — 19 октября 2026

Статус: пользователь подтвердил, что после исправления всё работает.

## Симптомы

При пересекающейся экипировке одинакового гаджета двумя игроками накапливались виджеты у хоста и клиента. Особенно заметно при одновременном доставании в игровом билде Steam. В диагностике разные экземпляры GA_J_Snap имели одинаковые Avatar и Controller.

## Причина

ULomAbilitySet — общий Data Asset. Он хранил изменяемые массивы AbilitiesHandles, EffectHandles и AddedAttributeSets для всех выдач набора.

При снятии экипировки одним игроком ClearAbility перебирал общие Handles, применяя их к Ability System только этого игрока, затем очищал все массивы. Handles другого игрока терялись, его Ability оставалась выданной. Последующая экипировка создавала новую Ability и ещё один комплект UI.

## Исправление

- Добавлена структура FLomAbilitySetGrantedHandles с Handles способностей и эффектов, ссылками на добавленные Attribute Sets и слабой ссылкой на исходный Ability System Component.
- Каждый ULomEquipmentItemInstance хранит собственную структуру GrantedAbilitySetHandles.
- ULomAbilitySet::GiveAbility стал const и передаёт результаты выдачи в отдельную структуру через OutGrantedHandles. Сам Data Asset больше не хранит состояние выдач.
- TakeFromAbilitySystem снимает только выдачи своей структуры с исходного ASC. Повторная очистка безопасна.
- Equipment передаёт свою структуру при выдаче и очищает её при снятии. Добавлены проверки серверных полномочий.
- Исправлена зависимость заголовков: в LomGameplayAbility.h include экипировки заменён предварительным объявлением.
- Вызовы выдачи начальных способностей из GameMode сохранены: им не требуется запись для последующего снятия.

Blueprint и UI Manager в рамках этого исправления не менялись. Защита от дублирования по классу виджета не добавлялась.
